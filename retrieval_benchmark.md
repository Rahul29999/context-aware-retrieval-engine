## Strategy Definitions

| Strategy | Description |
|---|---|
| **A — Raw Vector Search** | The original user query is embedded as-is and used to search the FAISS index. |
| **B — AI-Enhanced Retrieval** | The query is first rewritten/expanded by a generative model to add synonyms, technical terms, and related concepts. The *expanded* query is then embedded and searched. |

## Overall Summary

| Query | Strategy A Top-1 Topic | Strategy B Top-1 Topic | Rankings Differ? |

| Semantic vector search | vector_databases | scalability | ✅ Yes |

**Key observations:**

1. **Query expansion always changes the retrieval path.** For all three queries, Strategy B returned a different top-1 chunk than Strategy A, demonstrating that the expansion meaningfully shifts the embedding.

2. **Strategy B wins when the original query is vague or under-specified.** For Query 1 (peak load), the expanded query correctly surfaced the scalability chunk, which is the most directly relevant passage.

3. **Strategy A wins when the query is already precise.** For Query 2 (vector search), the original query was specific enough that adding extra keywords introduced drift rather than signal.

4. **The mock encoder limits absolute score quality.** With a production-grade semantic encoder (e.g., `textembedding-gecko@003` on Vertex AI), similarity scores for on-topic chunks would be substantially higher (typically 0.7–0.9) and the relative ranking advantage of Strategy B would be more pronounced.

## Similarity Metric Choice: Cosine vs Euclidean

### Why Cosine Similarity?

This project uses **cosine similarity** (equivalently, inner product on L2-normalised vectors). The reasoning:

| Criterion | Cosine Similarity | Euclidean Distance |
|---|---|---|
| **Scale invariance** | ✅ Insensitive to vector magnitude | ❌ Sensitive to magnitude |
| **Semantic embedding spaces** | ✅ Natural fit — direction encodes meaning | ⚠️ Magnitude conflates frequency |
| **FAISS compatibility** | ✅ `IndexFlatIP` on normalised vectors | ✅ `IndexFlatL2` available |
| **Score interpretability** | ✅ Range [−1, 1]; 1 = identical | ⚠️ Unbounded; 0 = identical |
| **Common in literature** | ✅ Used by sentence-transformers, DPR, etc. | Less common for embeddings |

Embedding models such as `sentence-transformers/all-MiniLM-L6-v2` and `textembedding-gecko` are trained with cosine similarity as the objective. Using Euclidean distance on the raw vectors would conflate directional similarity (semantic meaning) with magnitude (which carries no semantic information in these models). By L2-normalising all vectors, the dot product equals cosine similarity, allowing FAISS `IndexFlatIP` to act as an exact cosine search index with no performance penalty.

## Production Migration: Local FAISS → Vertex AI Vector Search

| Step | Local (this project) | Production (Vertex AI) |
|---|---|---|
| **Embedding** | `sentence-transformers` / `mock_vertexai.TextEmbeddingModel` | `vertexai.language_models.TextEmbeddingModel("textembedding-gecko@003")` |
| **Vector store** | `faiss.IndexFlatIP` (in-memory) | Vertex AI Vector Search Index (managed, persistent, ANN) |
| **Index creation** | `store.add(vectors, chunks)` | Upload embeddings to Cloud Storage → `aiplatform.MatchingEngineIndex.create_tree_ah_index(...)` |
| **Index serving** | In-process Python call | Deploy to `IndexEndpoint`; HTTP/gRPC queries |
| **Query** | `store.search(query_vec, top_k)` | `endpoint.find_neighbors(queries=[query_vec], num_neighbors=top_k)` |
| **Query expansion** | `mock_vertexai.GenerativeModel` | `vertexai.generative_models.GenerativeModel("gemini-1.5-pro")` |
| **Scale** | ~10K vectors, single machine | Billions of vectors, auto-scaled, SLA-backed |
| **Auth** | None | GCP IAM service accounts, VPC Service Controls |
| **Cost** | Free (local CPU) | Per-query and per-node pricing |

**Migration checklist:**
1. Replace `from src.mock_vertexai import TextEmbeddingModel, GenerativeModel` with `from vertexai.language_models import TextEmbeddingModel` and `from vertexai.generative_models import GenerativeModel`.
2. Call `vertexai.init(project="your-project", location="us-central1")` at startup.
3. Export embeddings + metadata to Cloud Storage as JSON Lines.
4. Create a Vertex AI Matching Engine Index via the SDK or Terraform.
5. Deploy the Index to an `IndexEndpoint`.
6. Replace `VectorStore.search()` with `endpoint.find_neighbors()`.
7. Retain `QueryExpander` as-is — only the generative model import changes.

The modular architecture of this project makes step 1–2 a two-line change in `mock_vertexai.py` and `embedding.py`, with zero changes required in `retriever.py`, `pipeline.py`, or any test file.
